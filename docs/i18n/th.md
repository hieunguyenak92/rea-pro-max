# REA Pro Max

**เข้าใจกลไก สร้างพฤติกรรมขึ้นใหม่ พิสูจน์ผลลัพธ์**

ชุดเครื่องมือวิศวกรรมย้อนกลับที่พัฒนาอย่างอิสระ พร้อม MCP ในเครื่อง สกิลเอเจนต์ และ CLI โดยตรง สำหรับ Claude Code, Codex และ client MCP ที่เข้ากันได้ เพื่อเปลี่ยนแอป ส่วนขยาย หรือฟีเจอร์เว็บที่คุณยังไม่คุ้นเคย ให้เป็นกลไกที่อธิบายได้ โค้ดที่รันได้ และข้อตกลงพฤติกรรมในขอบเขตจำกัดที่ตรวจสอบได้

## หน้าตาที่ดูดีเป็นเพียงจุดเริ่มต้น

ส่วนที่ยากเกิดขึ้นหลังการคลิก: คอนเท็กซ์ใดรับข้อความ สถานะถูกเก็บไว้ที่ไหน การยกเลิกหยุดอะไรจริง ข้อผิดพลาดใดส่งกลับถึงผู้เรียก และเหตุใดฟีเจอร์ที่สร้างขึ้นใหม่จึงล้มเหลวเมื่อใช้งานครั้งที่สอง

REA Pro Max นำคำถามเหล่านี้มาอยู่ในกระบวนการพัฒนา วิเคราะห์ JavaScript ที่แจกจ่ายแล้ว ระบุคำอธิบายที่เป็นไปได้หลายแบบ เลือกการทดลองที่แยกสมมติฐานเหล่านั้น จากนั้นสร้างพฤติกรรมที่ต้องการในโปรเจกต์ของคุณ เปรียบเทียบผลลัพธ์ การเปลี่ยนสถานะ และเหตุการณ์ที่สังเกตได้ เมื่อพบความต่าง ให้ลดเหลือชุดการกระทำที่ยังทำให้เกิดความล้มเหลวแบบเดิม

**สิ่งที่ส่งมอบคือฟีเจอร์ที่คุณขอ ซึ่งรันได้พร้อมหลักฐานประกอบ** เอเจนต์ในสภาพแวดล้อมของคุณทำหน้าที่เขียนโค้ดและทำงานกับรันไทม์ ส่วนเครื่องมือที่ให้มามีกลไกสำหรับวิเคราะห์ จัดอันดับการทดลอง ตรวจสอบพฤติกรรม และลดชุดการกระทำที่ทำให้เกิดปัญหา

## สั่งงานตามปกติ แล้วให้สกิลลงมือ

หลัง[ติดตั้ง](../INSTALL.md) ให้สั่งงานใน Claude Code ด้วยภาษาธรรมชาติ:

```text
/rea-pro-max ตรวจสอบกลไกบันทึกและกู้คืนข้อมูลของส่วนขยายนี้ แล้วสร้างพฤติกรรมดังกล่าวในโปรเจกต์ของฉัน ติดตามขอบเขต popup, content script, worker และ storage ตรวจสอบการคงอยู่ของข้อมูลหลังยืนยันว่า worker เริ่มทำงานใหม่จริง รักษาพฤติกรรมเมื่อเกิดข้อผิดพลาด และส่งมอบโค้ดที่รันได้พร้อมกรณีที่ทดสอบจริงและส่วนที่ยังไม่ได้ยืนยัน
```

ใน Codex ให้เลือกสกิลหรือใส่ `$rea-pro-max` หน้าคำสั่งเดียวกัน ระบุเป้าหมายและโปรเจกต์ที่จะรับโค้ด เอเจนต์จะเตรียมไฟล์ case ภายในให้เอง การสังเกตเบราว์เซอร์ แอป หรืออุปกรณ์จริงต้องมีเครื่องมือที่เหมาะสมในสภาพแวดล้อมของเอเจนต์

- **สร้างฟีเจอร์ที่เลือกขึ้นใหม่:** ครอบคลุมลำดับ ข้อผิดพลาด การยกเลิก และขอบเขตการเก็บสถานะ
- **เข้าใจส่วนขยาย MV3:** แยกคอนเท็กซ์ popup, content, page และ worker
- **ค้นหาขอบเขต Electron:** วิเคราะห์ซอร์ส main, preload และ renderer ที่แยกออกมาแล้ว
- **อธิบายข้อผิดพลาดถดถอยระหว่างสอง build:** ใช้อินพุตและผลกระทบที่เปรียบเทียบกันได้
- **ลดความซับซ้อนของปัญหาที่ทำซ้ำได้:** ตัดการกระทำออกโดยคงความล้มเหลวชนิดเดิม

## เครื่องมือชุดเดียว เริ่มต้นได้สามทาง

**v0.2 เพิ่ม MCP ในเครื่องพร้อมเครื่องมือ 12 ตัว** ให้เอเจนต์เรียกเคอร์เนลวิเคราะห์และตรวจสอบโดยตรง สกิลให้ขั้นตอนทำงาน ส่วน CLI ให้รันและตรวจผลอย่างอิสระ Runtime รวม parser และ SDK ทางการของ MCP แล้ว จึงไม่ต้องติดตั้ง npm เพื่อใช้งาน

### เชื่อม MCP กับ Claude Code หรือ Codex

แทนที่พาธสัมบูรณ์ด้วยพาธจริงของคุณ workspace ต้องเป็นโฟลเดอร์ที่มีอยู่และครอบคลุมเป้าหมายกับตำแหน่งผลลัพธ์ คำสั่งต่อไปนี้เป็นขั้นตอนให้คุณรันเอง ผลิตภัณฑ์ไม่แก้การตั้งค่าแอปอื่นโดยอัตโนมัติ

**พาธในคำสั่งด้านล่างใช้โครงสร้าง Git checkout** สำหรับ ZIP สกิลที่แพ็กไว้ใน Releases โฟลเดอร์ `rea-pro-max/` ที่แตกออกมาคือรากของสกิล ให้รัน `node scripts/rea-pro-max.mjs demo --out ./rpm-lab` ภายใน ใช้ `/absolute/path/to/rea-pro-max/scripts/mcp-server.mjs` สำหรับ MCP และคัดลอกทั้งโฟลเดอร์เมื่อติดตั้ง [โครงสร้างและคำสั่ง ZIP ภาษาอังกฤษ](../INSTALL.md#choose-your-package-layout) ไฟล์ Source code ที่ GitHub สร้างอัตโนมัติยังใช้โครงสร้าง checkout

```sh
claude mcp add --transport stdio --scope local rea-pro-max -- node "/absolute/path/to/rea-pro-max/skills/rea-pro-max/scripts/mcp-server.mjs" --workspace "/absolute/path/to/your-workspace"
```

```sh
codex mcp add rea-pro-max -- node "/absolute/path/to/rea-pro-max/skills/rea-pro-max/scripts/mcp-server.mjs" --workspace "/absolute/path/to/your-workspace"
```

เชื่อมต่อ host ใหม่ ตรวจรายชื่อเครื่องมือ แล้วให้เอเจนต์เรียก `get_capabilities` หากแอปเดสก์ท็อปมี PATH ต่างกัน ให้ใช้พาธสัมบูรณ์ของ Node [คู่มือ MCP ภาษาอังกฤษ](../MCP.md) มีการตั้งค่า JSON อาร์กิวเมนต์ ขีดจำกัด และการจัดการข้อผิดพลาด

เซิร์ฟเวอร์ใช้ stdio ในเครื่อง เมื่อเริ่มโดยตรงจะรอข้อความ MCP ไม่ได้เปิดหน้าจอโต้ตอบ:

```sh
node /absolute/path/to/rea-pro-max/skills/rea-pro-max/scripts/mcp-server.mjs --workspace /absolute/path/to/your-workspace
```

### ติดตั้งสกิลเพื่อสั่งงานตามธรรมชาติ

คัดลอก **ทั้งโฟลเดอร์** `skills/rea-pro-max` ไปยัง `.claude/skills/rea-pro-max` ในโปรเจกต์ Claude Code หรือ `.agents/skills/rea-pro-max` ใน Codex ส่วน `lib`, `scripts`, `references` และ `assets` เป็นส่วนหนึ่งของระบบที่รันได้ การคัดลอกแค่ `SKILL.md` จะทำให้ขาดกลไกจริง

จากนั้นใช้ `/rea-pro-max` ใน Claude Code หรือเลือกสกิล/ระบุ `$rea-pro-max` ใน Codex [INSTALL.md ภาษาอังกฤษ](../INSTALL.md) มีคำสั่งคัดลอกที่ไม่เขียนทับ ตำแหน่งส่วนบุคคล และวิธีสำหรับ Windows

### รัน CLI โดยตรง

เดโมด้านล่างรันได้โดยไม่ใช้ MCP เลือกสกิล MCP หรือ CLI ให้เหมาะกับสภาพแวดล้อม ไม่จำเป็นต้องใช้เซิร์ฟเวอร์ REA ต้นฉบับ

## เครื่องมือ MCP: จากอาร์ติแฟกต์สู่ผลลัพธ์ที่ส่งมอบได้

| เครื่องมือ | งาน |
| --- | --- |
| `get_capabilities` | ดูเวอร์ชัน workspace ขอบเขต ขีดจำกัด และนโยบายการรัน |
| `inspect_artifact` | วิเคราะห์เป้าหมายในขอบเขตแบบสแตติกและเก็บผลเต็มไว้ผ่าน handle |
| `read_artifact` | อ่านส่วนหรือหน้าที่ต้องการโดยไม่ส่งกราฟทั้งหมดซ้ำ |
| `create_case` | สร้าง case จากตัวระบุเป้าหมายที่ตรวจจริง |
| `revise_case` | ตรวจ patch และ revision ที่คาดไว้ก่อนอัปเดต |
| `record_observation` | เก็บข้อมูลสังเกต แหล่งที่มา authority และ bindings ที่ระบุ |
| `rank_probes` | จัดอันดับการทดลองที่อนุญาต แต่ไม่รันการทดลอง |
| `verify_behavior` | เปรียบเทียบไฟล์ข้อมูลสังเกตตามข้อตกลงจำกัด |
| `export_artifact` | เขียน JSON หรือ HTML แยกเดี่ยวลงไฟล์ใหม่ใน workspace |
| `run_owned_lab` | รันเฉพาะโมเดลควบคุมของ worker ที่โครงการเป็นเจ้าของและให้มา |
| `list_task_prompts` | ดูเทมเพลต 36 แบบตามกลุ่มและหน้า |
| `import_case` | ตรวจ case JSON ที่ส่งออกไว้แล้วนำกลับมาทำงานต่อ |

Handle เป็นตัวระบุทึบในหน่วยความจำของโปรเซส แคชมีขีดจำกัด หลังรีสตาร์ตหรือถูกนำออกจากแคช ให้ import case ที่บันทึกหรือวิเคราะห์ใหม่ ใช้ `read_artifact` อ่านเฉพาะส่วนที่ต้องการ schema ที่ client พบจริงเป็นสัญญาอาร์กิวเมนต์ที่แน่นอน

MCP จำกัดพาธเข้าออกที่ client เลือกให้อยู่ใน workspace ปฏิเสธ symbolic link และไม่เขียนทับผลเดิม นี่คือนโยบายรับพาธของเครื่องมือ ไม่ใช่ sandbox ระดับระบบปฏิบัติการสำหรับ Node หรือเครื่องมืออื่นของ host ไม่มี shell ตัวเปิดแอป ตัวควบคุมเบราว์เซอร์ หรือการรัน oracle ใดก็ได้ `run_owned_lab` รันเฉพาะโค้ดคงที่ของโครงการ

## ลองกลไกจริงก่อนเชื่อคำสัญญา

ต้องใช้ **Node.js 22+** เครื่องมือรันได้โดยตรง ไม่ต้องมี API key, `npm install` หรือเซิร์ฟเวอร์ REA ต้นฉบับ

```sh
git clone https://github.com/hieunguyenak92/rea-pro-max.git rea-pro-max
cd rea-pro-max
node skills/rea-pro-max/scripts/rea-pro-max.mjs demo --out ./rpm-lab
```

เปิด `rpm-lab/report.html` ในเบราว์เซอร์ แล็บสังเคราะห์ที่โครงการเป็นเจ้าของรัน worker อ้างอิงและ worker ที่มีข้อผิดพลาดใน **โมเดล JavaScript ที่ควบคุมได้ โดยใช้ Chrome API จำลอง** ผลวิเคราะห์ การจัดอันดับการทดสอบ การตรวจจับความต่าง และการลดชุดการกระทำมาจากการคำนวณจริงของเคอร์เนล แต่ไม่ได้พิสูจน์การหยุด worker ใน Chromium จริง การตรวจรันไทม์ที่ทำแยกต่างหากอยู่ใน[บันทึกการตรวจสอบ](../VALIDATION.md)

วิเคราะห์อาร์ติแฟกต์ตัวอย่างได้ด้วยตัวเอง:

```sh
node skills/rea-pro-max/scripts/rea-pro-max.mjs inspect ./rpm-lab/fixtures/mv3/reference --out inspection.json
node skills/rea-pro-max/scripts/rea-pro-max.mjs report inspection.json --out inspection.html
node skills/rea-pro-max/scripts/rea-pro-max.mjs prompts --target mv3
```

ใช้พาธผลลัพธ์ใหม่ เครื่องมือจะไม่เขียนทับผลเดิมโดยไม่แจ้ง ดู[คู่มือติดตั้งและ CLI](../INSTALL.md) ภาษาอังกฤษ สำหรับการตั้งค่าสภาพแวดล้อมและคำสั่งเพิ่มเติม

## ความเชี่ยวชาญที่ตรวจสอบกลไกได้

| ความสามารถ | คุณค่าที่เพิ่มให้การตรวจสอบ |
| --- | --- |
| วิเคราะห์ขอบเขตอาร์ติแฟกต์ | แยก AST ด้วย Acorn แยกคอนเท็กซ์การทำงาน ระบุเส้นทางสื่อสารที่เป็นไปได้ ตำแหน่งซอร์สที่แน่นอน และไดเจสต์เนื้อหา `inspect` ไม่รันโค้ดเป้าหมาย |
| สมมติฐานที่แข่งขันกัน | ระบุคำทำนายและขั้นตอนทดสอบที่มีการรีเซ็ต แทนการยอมรับคำอธิบายแรกที่ฟังดูสมเหตุสมผล |
| จัดอันดับการทดลองอย่างระมัดระวัง | ประเมินจำนวนสมมติฐานที่ตัดออกได้ในกรณีเลวร้ายที่สุดต่อค่าใช้จ่ายที่ระบุ กรองตามความสามารถ ผลกระทบที่อนุญาต และงบประมาณ คำทำนายที่ขาดยังคงเป็นข้อมูลไม่ทราบ |
| ผูกหลักฐานกับบริบท | ใช้ตัวระบุเป้าหมาย สถานการณ์ การรีเซ็ต และ toolchain เพื่อไม่นำข้อมูลที่เข้ากันไม่ได้มาใช้อนุมานปัจจุบัน แฮชระบุเนื้อหา ไม่รับรองว่าเกิดการรันจริง |
| ตรวจสอบพฤติกรรมในขอบเขตจำกัด | ให้ผล `pass`, `fail`, `unknown` สำหรับ output, state, effects และ trace โดยรักษาเหตุการณ์ซ้ำและลำดับที่มีความหมาย |
| ลดชุดการกระทำที่ทำให้ล้มเหลว | ลบการกระทำภายในงบประมาณ ตรวจ oracle ซ้ำ และรักษาลายนิ้วมือความล้มเหลวเดิม ไม่รับประกันชุดที่สั้นที่สุดในทุกความเป็นไปได้ |
| เวิร์กเบนช์ในเครื่อง | HTML แบบแยกเดี่ยว มีการค้นหา ตัวกรองคอนเท็กซ์ การเลือกหลักฐาน และส่งออก JSON ทั้งหมด ไม่ต้องใช้ backend หรือ CDN |
| พรอมป์ต์งาน 36 แบบ | ครอบคลุมเว็บ ส่วนขยาย เดสก์ท็อป และกลุ่มมือถือ พร้อมระบุเงื่อนไข การมีเทมเพลตไม่ได้รับรองว่า provider ผ่านการตรวจแล้ว |

ตัววางแผนเลือกคำถามถัดไป แต่ไม่รันการทดลอง ตัวตรวจสอบเปรียบเทียบข้อมูลที่ได้รับ แต่ไม่ยืนยันด้วยตัวเองว่ารันไทม์ทำงานจริง สกิลจะให้เอเจนต์ทำงานเหล่านั้นและเก็บหลักฐาน

## ขอบเขตชัดเจน เพื่อให้ผลลัพธ์มีความหมาย

**การวิเคราะห์ในตัว v0.2:** ไฟล์ JavaScript และซอร์สเว็บ Manifest V3 และ Electron ที่แยกออกมาแล้ว นิพจน์แบบไดนามิก ไวยากรณ์ที่ไม่รองรับ import ที่ขาด และขีดจำกัดทรัพยากรจะแสดงไว้อย่างชัดเจน

**เคอร์เนลที่ไม่ผูกกับ provider:** จัดการ case จัดอันดับการทดลอง เปรียบเทียบพฤติกรรมในขอบเขตจำกัด ลดชุดการกระทำ และสร้างรายงานในเครื่อง `shrink` จะรันโมดูล oracle `.mjs` ที่คุณเป็นผู้จัดหาและควบคุมโดยตรง

**งานขั้นสูงผ่านเครื่องมือของสภาพแวดล้อม:** มีพรอมป์ต์ native, managed, Android, Apple, React Native, Flutter, Tauri และ WebAssembly การวิเคราะห์ลึกต้องอาศัยเครื่องมือที่เหมาะสมและมีใช้งานจริง รุ่นนี้ไม่มี decompiler อเนกประสงค์ รันไทม์มือถือ ตัวแยกแพ็กเกจทุกชนิด หรือเอนจินกู้คืนความหมาย การตรวจพบรูปแบบไฟล์หรือมีเทมเพลตไม่เท่ากับการเชื่อมต่อที่ตรวจสอบแล้ว

CLI ไม่ส่งคำขอเครือข่ายหรืออัปโหลด telemetry ส่วน AI host และเครื่องมือภายนอกมีนโยบายข้อมูลของตนเอง รายงานอาจมีพาธ โค้ด และค่าที่ละเอียดอ่อน อ่าน[ความเป็นส่วนตัวและขอบเขตการรัน](../PRIVACY.md) ภาษาอังกฤษ ก่อนแชร์

## สิ่งที่คุณได้รับหลังจบงาน

งานสร้างใหม่ควรส่งมอบซอร์สที่รันได้ วิธีเริ่มต้น ข้อตกลงพฤติกรรมที่เลือก การกระทำที่ทดสอบจริง หลักฐาน JSON และข้อจำกัดที่เหลือ ผล `pass` ใช้กับกรณีที่ตรวจสอบเท่านั้น ไม่ได้ยืนยันว่าแอปทั้งหมดเทียบเท่ากัน

แล็บส่งออก `inspection.json`, `case.json`, `planner.json`, `reference.json`, `candidate.json`, `verification.json`, `reduction.json`, `lab.json` และ `report.html` แบบแยกเดี่ยว คุณตรวจแต่ละบันทึก เก็บไว้กับโปรเจกต์ และส่งออก JSON ทั้งหมดจากเวิร์กเบนช์ได้

## ตัวอย่างจริงและหลักฐานที่ย้อนดูได้

**ค้นหา Unicode:** [แอปที่รับการสร้างใหม่](../../examples/recovered-search/CONTRACT.md) สร้างข้อตกลงค้นหาที่เลือกจาก web fixture: NFKC ตัวพิมพ์เล็กตาม locale การจับคู่ substring ลำดับคงที่ และ ID แบบสตริง แอปอ้างอิงและแอปที่สร้างใหม่เปิดแยกกัน กรณีจำกัดและข้อจำกัดอยู่ใน [VALIDATION.md](../VALIDATION.md) ตัวอย่างนี้เขียนและตรวจโดยเอเจนต์เดียวที่เข้าถึงซอร์ส ไม่ใช่การทดลองแบบปกปิดหรือ benchmark ผลเชิงเหตุของสกิล

## การตัดสินใจเชิงลึกในเอนจิน

คะแนนการทดลองคือจำนวนสมมติฐานที่ตัดออกได้ในกรณีเลวร้ายที่สุดหารด้วยค่าใช้จ่ายที่ระบุ โดยกรองความสามารถ ผลกระทบที่อนุญาต และงบประมาณก่อน หากทุกสมมติฐานขัดกับข้อมูลที่เข้าเกณฑ์ อาจได้ `model_incomplete` หากไม่มีการทดลองที่อนุญาตให้แยกทางเลือก อาจได้ `no_discriminating_probe` ความไม่แน่นอนจะไม่ถูกแปลงเป็นเปอร์เซ็นต์ความมั่นใจที่ไร้หลักฐาน

ตัวตรวจสอบปรับมาตรฐานได้เฉพาะพาธ metadata ที่ระบุ ไม่ลบความต่าง output/state/effects/trace ข้อตกลงลำดับรวมและลำดับตาม channel รักษาเหตุการณ์ซ้ำกับลำดับสำคัญ ตัวลดชุดการกระทำตรวจ oracle ซ้ำ รองรับ reset ก่อนทุกครั้ง และเก็บลายนิ้วมือความล้มเหลวเดิม ความน้อยที่สุดจำกัดอยู่ที่การลบที่ตรวจจริง

## คำถามและการแก้ปัญหา

**ต้องใช้ทั้ง MCP และสกิลไหม?** ไม่จำเป็น MCP ให้เครื่องมือมีโครงสร้าง สกิลให้คำแนะนำการทำงาน และ CLI ยังรันตรงได้

**สกิลเขียนฟีเจอร์ให้ไหม?** สกิลสั่งเอเจนต์ของ host ให้พัฒนาและรันในโปรเจกต์ของคุณ รายงานอย่างเดียวยังไม่จบงานสร้างใหม่

**ปิด MCP แล้ว case ยังอยู่ไหม?** ส่งออก JSON ก่อนปิด แล้วใช้ `import_case` ในเซสชันใหม่ Handle ไม่คงอยู่ข้ามโปรเซส

**ทำไมได้ `unknown`?** ตรวจข้อมูลไม่ครบ อินพุตที่เทียบกันไม่ได้ และ bindings ของ scenario/reset/toolchain/verifier ผลนี้ไม่กลายเป็น `pass` อัตโนมัติ

| ปัญหา | ขั้นตอนต่อไป |
| --- | --- |
| MCP ไม่เริ่ม | ตรวจ Node22+ พาธสัมบูรณ์ และ workspace ที่มีอยู่ |
| ไม่เห็นเครื่องมือ | เชื่อม host ใหม่ ดูสถานะเซิร์ฟเวอร์และสิทธิ์ MCP |
| ใช้ handle ไม่ได้ | Import case ที่บันทึกหรือวิเคราะห์ใหม่หลังรีสตาร์ต/นำออกจากแคช |
| Revision ขัดแย้ง | อ่าน case ล่าสุดและใช้ revision จริง |
| เกินขีดจำกัดหรืออยู่นอกขอบเขต | ลดขอบเขตอาร์ติแฟกต์หรือเลือก workspace ที่ถูกต้อง |
| มีไฟล์ผลลัพธ์แล้ว | ใช้ชื่อใหม่เพื่อรักษาหลักฐานเก่า |

ทิศทางต่อไปคือวิเคราะห์สแตติกได้ลึกขึ้นโดยระบุความไม่แน่นอน เพิ่มตัวอย่างฟื้นคืนฟีเจอร์ที่ทำซ้ำได้ และเชื่อม provider ตามเวอร์ชันเมื่อทดสอบรันได้จริง นี่คือแผนพัฒนา ไม่ใช่การรองรับที่เผยแพร่แล้ว
